# 不安装 EllesmereUI 的可行性（2026-10-01）

## 结论

**当前 1.4.2 仍不能独立美化集合石。可以改成「有 EllesmereUI 就接入、没有就独立绘制」双模式，但本次仅做分析，没有取消依赖。**

这里的 EUI 指本插件接入的 **EllesmereUI**，不是 ElvUI/其他同名整合包。

## 从当前源码确认的依赖

| 位置 | 依赖与影响 |
| --- | --- |
| `Core.lua` 文件入口 | 找不到 `EllesmereUI.RegisterSkin` 就直接返回；共享 helper 也不会初始化。 |
| `Core.lua` 注册回调 / `Panels.lua:ns.Boot(S)` | 只有 EUI 触发回调，才解析 MeetingStone/NetEaseGUI、设置 `ns.S`、安装 hooks、接管原设置页并注册界面美化页。 |
| `Widgets.lua`、`Core.lua`、`Controls.lua` | 调用 EUI 的面板、按钮、边框、输入框、下拉、字体、图标、配色和主题更新接口。只是删除 TOC 依赖或入口判断会引发 nil 调用，不能获得独立美化。 |
| `MeetingStoneEllesmereUI.toc` | `OptionalDeps` 只表示插件管理器允许加载，不保证功能独立；图标路径也指向 EllesmereUI 的素材。 |
| 已安装 `EllesmereUIBlizzardSkin_SkinAPI.lua` | 皮肤接口委托 WindowEngine；缺少子插件、客户端阻断或第三方皮肤开关关闭时，不能假设回调一定执行。 |

当前运行时代码直接调用 **16 类** `ns.S` 接口： `Panel`、`Inset`、`FadeRegions`、`Button`、`StateButtonLabel`、`EditBox`、`Dropdown`、`CloseButton`、`PageButton`、`SquareIcon`、`White`、`Font`、`GetFont`、`GetPanelColor`、`GetAccentColor`、`OnLooksChanged`；另有通过可选接口调用的标签/表头能力。复选框外观已在本插件的 `Controls.lua` 自绘，但其强调色仍来自 `ns.S`。

此外有两种硬编码的外部素材：`Panels.lua` 与 TOC 使用 EUI 的 `eg-logo.tga`，`Widgets.lua` 子菜单箭头使用 `eui-arrow-right.png`。删除依赖声明不能解决启动、绘制接口和资源缺失。

用户本次授权的是「依赖不多就直接改」。复核后不满足这个前提：需要补齐独立绘制后端、拆分启动流程和处理共享输入框，而非替换几处配色调用。因此当前版本只修复反馈问题，不冒充已经支持无 EUI。

## 可以复用什么

- 21 项美化配置及保存格式；大部分面板布局、标签、行样式逻辑。
- 原生设置适配器、筛选合并、快捷筛选刷新和赛季副本全选/全不选。
- 新开关绘制：纯 WoW Frame/Texture，不依赖 EUI 贴图。
- 集合石仍是前置：需要它提供面板、NetEaseGUI、LibClass、Ace 与配置定义。MeetingStoneEX 的地下城增强仍是可选功能，未加载时只提供可用部分。

## 推荐第二阶段实现方案

1. 把 Core 的共享初始化与 EUI 注册拆开，用一次性启动状态处理 `PLAYER_LOGIN` / `ADDON_LOADED` 和后加载插件。
2. 保留现有 `ns.S` 调用面作为绘制层接口。EUI 就绪时使用当前后端；确定未安装/未加载 EUI 时，使用本插件的独立后端。
3. 用公开 WoW API 实现独立后端，提供自己的默认暗色背景、强调色、中文系统字体、边框、下拉箭头、按钮与标签状态；不要拷贝整套 EUI 引擎或修改它的 SavedVariables。
4. EUI 存在但用户主动关闭第三方美化/本皮肤时，不能静默用独立后端绕过关闭意图。应明确区分「依赖不存在」和「用户关闭美化」。
5. 一次会话只选一个绘制后端，防止后加载 EUI 导致重复 hooks/背景；切换后端可要求重载。
6. 保留并扩展 1.4.2 `BrowseInputs.lua` 的可逆接管：专门处理借用的暴雪 `LFGListFrame.SearchPanel.SearchBox`：集合石隐藏会归还此输入框。独立模式应保存/恢复外观，或明确与暴雪组队查找器美化协调，不能意外改全局界面。
7. 添加本插件自己的图标或无外部素材的回退；核对新增素材许可。

## 验证矩阵

- 仅集合石 + 本插件；再加 EX。
- EUI 主插件缺席、仅主插件存在、BlizzardSkin 子插件关闭、完整 EUI。
- EUI 总开关/第三方开关/本皮肤开关关闭，确保不绕过用户选择。
- EX 或 EUI 后加载、反复打开面板、主题切换、重载后设置保留。
- 中文字形、不同 UI 缩放、战斗中使用非保护控件、暴雪/集合石搜索框来回归还。
- 两后端分别跑现有设置、筛选及新开关测试，并做客户端视觉与搜索测试。

这是明确可行的后续工作，但不是「去掉一行前置」；当前发布包没有承诺无 EUI 支持。

## 移除依赖对效果与功能的影响

- 直接删除依赖/停止加载 EUI：当前版本不会完整启动，美化及由它注册的设置/筛选增强也会失效；集合石自身功能不等于本插件功能。
- 实现独立后端：布局、直角开关、设置项、合并筛选、全选/全不选和保存逻辑可以保留。默认外观可以接近现状，但字体、细线、缩放、图标和共享控件需逐项对照，不能先承诺逐像素一致。
- 没有 EUI 时，不能继续跟随 EUI 的主题/强调色/字体设置，需要本插件的默认值或自有配置；Logo/箭头素材需替换。
- 推荐双模式：EUI 存在且启用时保留现有后端，无 EUI 时使用独立后端。这样更容易保持老用户的效果。移除依赖并非内存问题的已证实解法。
