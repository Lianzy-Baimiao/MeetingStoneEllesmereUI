# 1.4.5 输入控件、开关与设置页

## 范围

- `Controls.lua`：通用下拉及只替换视觉的 switch。`BrowseInputs.lua`：主页两个控件的显式绘制与借用/归还管理。
- `Widgets.lua`：NetEaseGUI CheckBox 使用同一开关；裸 CheckButton 仅在尺寸和原始复选框贴图匹配时接入。列表整行、单选/菜单标记不冒充开关。其他插件和暴雪全局复选框不批量修改。
- 设置页开关控件 32×22，显示 28×14；原有密集行保留原点击尺寸，20×12 紧凑轨道不挤压职责/地下城文字。
- 轨道、边框和滑块均为单个纯色矩形，无圆角、无阶梯拼接。尺寸、绝对边缘和边框厚度按物理像素取整；主题、UI/窗口缩放和设置页布局变更会重新绘制。
- 原按钮仍是 CheckButton；正常操作的原回调、文字点击、`SetChecked`、禁用/确认撤回、全选/全不选都保留。勾选是右侧亮色，关闭是左侧暗色，禁用整体降低透明度。不使用逐帧轮询。
- 主页搜索控件借自暴雪：不改搜索文本、焦点、父节点、锚点、Enter/自动完成/清除回调。原来只调用 EUI EditBox 原语，遇到已有 bg 标记会直接返回，无法修复后续恢复的旧纹理。现在用独立子图层承载背景，按控件实际归属与面板显隐接管/恢复原纹理 alpha；已有 EUI 直接背景仅在借用期间遮蔽，不访问其私有 FFD。
- 1.4.3 根据 `游戏测试/QQ20261001-225015.png` 修复高度差：原下拉为 170×26，原搜索框截图约为 220×18（后者为截图推算，不冒充客户端 XML 常量）。搜索框借用期间匹配下拉的实际显示高度，默认 26；保持宽度 220、原间距 20 与 LEFT→RIGHT 居中锚点。美化层仍贴合真实控件，因此显示边框和点击范围一起对齐。原生搜索框归还时恢复每次借用前的高度。
- 输入文字与 Instructions 提示只修改字体路径、字号、描边规格，与 `labelFontSize` / EUI 字体同步；不修改颜色、文本、字体对象、输入内边距或光标/焦点。字体规格与 claimed 标记按借用周期恢复；晚执行的 OnShow 字体重置由已有下一帧校正覆盖。主题回调、字号/文字增量设置与主窗口缩放均可重绘。
- 主页下拉使用同一专用绘制层，即使先被其他 pass 标记 done 也不跳过；保留原按钮、文字、选择回调及子按钮，画中性箭头并隐藏旧的 ChatIcon 纹理。
- 每个控件只创建一次图层和 hooks，反复 Show/借用不会新建纹理；延迟校正按页面去重，无 OnUpdate、无持续计时器。不同插件若在更晚时机反复强制覆盖，仍需游戏内诊断，不承诺覆盖一切皮肤冲突。
- `SettingsLayout.lua` 统一两页的内部坐标、字体样式、控件列与页脚边距；美化页注册时继承原设置页 padding 与 inset 高度，修复外层 3/10 的差异及关键词模块版本的高度差异。
- 「界面美化」为左侧三分类、右侧单列设置行、独立滚动区，与原生「设置」新版一致；保留全部 21 项、百分比/字号转换和颜色取消。
- 「恢复默认」增加确认，仅重置美化配置，不清空集合石/EX 的组队筛选。数字编辑先保留草稿，失焦/Enter 保存，Esc 取消。

## 职责互斥（1.4.1）

`Panels.lua` 只包装 EX 的四个已知职责复选框 OnClick：缺坦克/已有坦克、缺治疗/已有治疗。新勾选与旧选项冲突时，在原 OnChanged/saveAdvancedFilter 之前撤回新选择并提示，避免原代码仅警告但仍保存矛盾条件。普通有效点击仍调用原脚本，不直接写入 EX 或暴雪筛选数据、不全局改写对话框。

首页快捷项读取原控件的最终状态，仅在有效状态改变后安排搜索。关闭快捷栏不影响原生筛选的互斥保护。程序化重置、批量副本勾选与其他不相关职责不受此包装影响。已有历史矛盾数据不会在加载时强行清理，可以手动取消多余条件。

## 1.4.5 首页右侧两行与专精职责说明

`BrowseJoinControls.lua` 管理唯一一组原生首页复选框。当前本体把它们保存为构造函数局部变量，所以仅在 BrowsePanel 的直接 CheckButton 子节点中，按完整原标签识别，并缓存原对象；不搜索其他面板，不创建替代按钮。两个控件未同时出现时不调整布局，之后的页面重开或刷新可补齐。

原几何是 quick 居中于 SearchBox、auto 在 quick 上方 24 单位，导致整组中心比输入框高 12 单位。这不是简单的边框或字号问题。现改为输入框中心上下各 10 单位，两行均 24×20、相同水平间距 10，按钮原回调与开关状态不变；每次布局后重新执行 Switch 重绘，确保显示矩形与新坐标相符。字号更新沿用共享标签字体，并由原 CheckBox:SetText 重新计算文字点击范围。与 1.4.3 的高度修复、主题及主窗口缩放刷新共用入口。

标签数据与当前适配的集合石本体 OnItemDoubleClick 完全同源：`GetSpecialization()` 获取当前专精序号，再取 `GetSpecializationInfo` 的第 5 个返回值。TANK / HEALER / DAMAGER 分别显示「双击加入（防御）」「双击加入（治疗）」「双击加入（输出）」。不显示专精可用职责或地下城查找器多选状态；API 缺失、报错或专精尚未就绪时显示「专精未就绪」，不猜测报名身份。

只监听 PLAYER_ENTERING_WORLD 和 PLAYER_SPECIALIZATION_CHANGED（仅玩家）。页面隐藏时不读 API、不改文字，重开时重读；监听器只创建一次，无轮询、无定时器。标签未变时不重复 SetText。悬浮说明为「双击队伍时，按当前专精对应的职责申请加入」。

**1.4.4 的数据源选择错误已纠正：**当 GetLFGRoles 勾选防御+输出而当前专精为治疗时，本体实际仍以治疗申请；上一版显示「防御+输出」会误导用户，用提示解释差异不能解决它。1.4.5 移除 GetLFGRoles 读取和 SetLFGRoles 后置钩子，改为让显示服从本体实际申请逻辑。本次不改原双击回调、ApplyToGroup 参数构造或原复选框保存行为。

## 1.4.14 选中配色与固定深色边框（现行规则）

此前 1.4.12/1.4.13 的主题色/灰阶方案已被本节替代，历史见 CHANGELOG。根因是将装饰边框和选中状态共用强调色，且 EUI 的动态主题色未必是图标绿。现在两者分开绘制。

- 位置：「界面美化 → 窗口与标签 → 选中状态使用职业色」，分类第一项，默认 `useClassColor = false`。
- 关闭：固定 EUI 图标绿 `12/255, 210/255, 157/255`（#0CD29D，取自 eg-logo.tga 主色）。不读取会随主题变更的 `ELLESMERE_GREEN` 或 `ns.S.GetAccentColor()`。
- 开启：从 `UnitClass("player")` 的第二返回值取得职业 token，优先 `C_ClassColor.GetClassColor`，回退 `RAID_CLASS_COLORS`。职业信息未就绪则使用图标绿。
- 旧 `useThemeColor` 值不参与配色、不迁移成职业色；已有明确保存的 `useClassColor` true/false 保留，缺失时默认关闭，恢复默认回到绿色。不修改 EUI 全局主题、集合石/EX 本体或真实 SavedVariables。

| 控件状态 | 自绘边框 | 内部轨道/填充 | 滑块/勾号 |
| --- | --- | --- | --- |
| switch 未开启 | `.22` 深灰 | `.10` | 左侧 `.40` 暗灰方块 |
| switch 已开启 | `.22` 深灰 | `.18` | 右侧绿色/职业色方块 |
| 多选框未选 | `.22` 深灰 | `.10` | 无勾号 |
| 多选框已选 | `.22` 深灰 | 绿色/职业色 | 去色后按底色明暗使用深色/浅色勾号 |

输入框/下拉框/活动说明视口等通过 `SetControlChrome` 绘制的边框也固定 `.22,.22,.22`，退出强调色注册表。保留输入卡片原底色、直角、物理像素对齐和禁用整体 alpha `.4`。列表多选不转换为 switch，不替换原按钮或事件。

`ns.Accent` 弱键注册表只管理列表选中填充/竖条、页签下划线和两设置页导航标记；`ns.RefreshSwitches()` 管理开关与多选框。设置变化只重绘颜色，不重建面板、不触发搜索、不修改输入/勾选，不新增轮询或逐控件定时器。EUI 自己的原语仍由其 API 管理，此本地选项不改写外部主题和边框。
