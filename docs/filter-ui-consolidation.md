## 已实施的结构

- 保留原 AdvButton 对象，将其改为唯一「筛选」入口；旧 ExSearchButton 移至隐藏容器。
- 三个旧弹窗外壳也移至隐藏容器，原生 Show/Hide 回调照常运行但不能再弹出独立窗口。
- 只将原 Inset 和操作按钮迁入统一窗口；原复选框、范围输入、回调闭包和配置归属不变。
- 单列滚动内容、固定顶部高级展开入口、固定底部操作区，窗口高不超过正常主窗高度，宽 300px；高级项默认折叠，展开时滚动定位。
- 赛季地下城使用原地下城条件，其他活动使用原组队条件。切类型不会改变统一窗口开关状态；按类别加载原高级配置。
- 「应用并刷新」复用原 RefreshFilterButton：地下城分支调用原匿名“搜索更多队伍”按钮，先保存其闭包内 minimumRating 再搜索；其他分支使用保存下来的原刷新 OnClick。
- 「重置高级」仍执行原 ResetFilterButton 回调；没有合并清空三种数据的操作。
- 原 noAutoFilterPopup 配置不删除，但统一窗口只手动打开，不再随类型选择自动弹出。旧控件接管失败时保留原兼容路径。

﻿# 合并「过滤器 / 高级过滤」的可行性

状态：分析方案，1.2.4 尚未合并按钮。依据本机安装的 MeetingStone 与 MeetingStoneEX 源码。

## 结论

可以合并成一个入口和一个窗口，但应只统一展示和窗口管理，保留各自的过滤逻辑、配置归属和刷新回调。两者不是重复功能，不应删除其中之一，也不应因为窗口关闭就清除条件。

## 现有功能

| 入口/内容 | 功能 | 数据与行为 |
| --- | --- | --- |
| 过滤器：地下城搜索 | 赛季地下城选择、缺/已有职责、同职业过滤、最低评分、搜索队伍；另有 Roll 币池工具入口 | MeetingStoneEX `CreateBlzFilterPanel` 创建；职责条件走其原回调及 `C_LFGList.SaveAdvancedFilter`，随后搜索。部分条件也用于 EX 的本地列表过滤。 |
| 过滤器：组队过滤器 | 坦克/治疗/输出、多个条件的“或”模式、屏蔽提示 | MeetingStoneEX `CreateExSearchButton` 创建；写入 `MEETINGSTONE_UI_DB`，调用 `ActivityList:Refresh()`。不是大秘境那组 `needs*/has*` 条件。 |
| 高级过滤 | 团长大秘境评分、装备等级、Boss 击杀数、活动创建时长、队伍人数的上下限 | MeetingStone `BrowsePanel` 创建 `self.filters`，通过 `Profile:SetFilters(categoryId, ...)` 按活动类别保存；`UpdateFilters` 应用到活动列表。 |

具体来源：
- `MeetingStone/Module/BrowsePanel.lua`：活动下拉框 `OnSelectChanged`、高级过滤条件表、两个原生按钮回调、`UpdateFilters`。
- `MeetingStoneEX/MeetingStoneEX.lua`：`createSeasonFilter`、`CreateBlzFilterPanel`、`CreateExSearchButton`、`CheckJobsFilter`。

## 推荐的交互

主界面只保留一个「筛选」按钮，点击打开唯一的过滤窗口：

1. **活动条件**：根据活动类型显示赛季地下城条件或普通组队条件；无效的条件不显示。
2. **高级条件**：保留原有五项范围过滤，可折叠以控制窗口高度。
3. 同一个关闭按钮，关闭窗口不清空筛选，也不隐藏首页适用的快捷项。
4. 切换活动类型时，仅替换窗口内适用内容、加载该类型原有高级条件；不另开弹窗。
5. 内容过多时使用滚动区域，避免把三个 200px 宽的旧窗口简单竖向堆叠成超高面板。

## 实施边界与风险

- 复用原控件/回调，不重写过滤算法，不直接合并三套保存数据。
- 保留两种评分字段的原始语义，不能因为都叫“评分”就去重。
- 高级过滤现有“重置”只清理高级条件；地下城窗口名为 `ResetFilterButton` 的局部变量实际是“搜索更多队伍”，不能当成清空按钮调用。
- 若提供统一“清空所有条件”，必须另行定义范围；建议先保留分组清空，避免意外重置其他类别配置。
- 统一“应用/刷新”要调用正确的保存流程，再进入既有搜索冷却；不能只刷新列表而遗漏服务器过滤结果。
- 接管三个原窗口的 Show/Hide、锚点与延迟初始化，保持手动点击、恢复活动类型和快捷栏同步正常。
- 因原窗口的选择回调和按钮直接调用 Show/Hide，不能只隐藏一个按钮：那样仍有不可达功能或自动弹窗重叠。
- 必须增加统一入口、类别切换、关闭窗口、首次 EX 初始化、配置恢复、条件重置及搜索冷却测试。

## 本轮已实施的独立修复

- 快捷栏根据活动类型与原职责控件自身的 IsShown 状态显示，不依赖弹窗的 IsVisible/IsShown。
- 活动选择完成后，如果高级过滤已打开，关闭原回调自动打开的类型过滤弹窗。不要在类型弹窗的 OnShow 中强制高级过滤优先，因为原手动按钮在 Show 之后才关闭另一张卡，那样会破坏手动切换。
- 这两项修复不依赖未来是否采用合并方案。
